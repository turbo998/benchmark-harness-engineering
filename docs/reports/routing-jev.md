# Jev 路由集成：历史事实整理

**来源性质：** `anonymized_reported`，中英文两个页面，未独立复现。
来源演示的 Model Router 版本为 2.1.1，确切测试日期未确认。
数据见 [JSON](../../data/reported/routing-jev/report.json)。

## 测量对象

报告观察规则优先、typed-choice 决策兜底、默认模型回退及同交互粘性。
候选模型描述是路由输入，选出模型之后才执行真正的回答/编码。
这些是集成示例，而非成体系的准确率或最终任务质量实验。

| 示例类别 | 来源所选模型 | 观察到的决策耗时 |
|---|---|---|
| 问候 | gpt-4.1-mini | 初次约 1400ms，后续约 300ms |
| 编码 | gpt-4.1 | 约 290–330ms |
| 推理 | gpt-5.4 | 约 300ms |
| 翻译规则 | gpt-4o | 规则命中，不调用 Jev |

一个多轮示例有 5 次后端模型请求，只作 1 次路由决策，第一次约 320ms，
后续粘性复用标为 0ms。来源对比的 LLM 决策约 2–4 秒。
复用 0ms 不是“模型零延迟”，规则命中也不是一次 Jev 预测。

## 限制与安全边界

**300ms 是决策阶段时间，不是 TTFT、回答生成或编码任务完成时间。**
少量示例、不同冷暖连接和复用行为不能证明路由挑选到了全局最优模型。
本页没有汇总准确率、计费 token 或已核验费用，数据中保留未知值。

即使后端在 Azure，Jev 仍会收到用于决策的请求/state，因此不能称所有数据留在
Azure。历史报告的 BYOK/协议集成也不等于本 harness 已验证身份隔离或可启用 live。
原截图、默认口令、密钥配置和完整示例输入未转载。
新路由 pack 应独立定义可接受选择、冻结描述、记录冷暖/粘性状态与
`routing_latency`，并另测被选模型的实际输出质量。
